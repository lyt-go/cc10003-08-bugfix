# 指标口径与分析实验平台

面向业务指标定义、口径管理、聚合查询、分群分析、A/B实验设计、分析方案管理与数据服务发布的数据分析工程平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 标签分群生效链路

分群是否生效由**标签版本**与**人群最终规模**共同决定，链路为：

```text
标签发布（版本+1、规则集合校验）
  └─ 分群提交规则校验（草稿/已失效 → 规则校验中，同规则指纹重复提交幂等）
       └─ 刷新计算（批次号 + 互斥锁，首份完整结果胜出）
            └─ 同一事务回写：分群最终规模 + 标签覆盖对象数（失败整体回滚，不单侧改写）
                 └─ 生效校验（规模边界 + 标签已发布 + 版本一致 + 规则集合有效）
                      └─ 已生效；标签换版后自动回到规则校验中，旧最终规模留存追溯
```

关键规则：

- 规模边界：最小规模不得大于最大规模（相等允许）；覆盖对象数为 0、低于下限或超过上限
  一律拒绝生效，并在返回信息与分群「校验原因」中逐条说明。
- 标签前置：标签未发布、分群引用版本与标签当前版本不一致、规则集合引用不存在或未发布的
  维度属性，均拒绝生效。
- 状态机：分群只允许 `草稿 → 规则校验中 → 已生效 → 已失效` 推进；已失效可重新提交校验
  （重试），其他逆向跳转拒绝。
- 换版传播：已发布标签被修改即退回草稿，重新发布版本号 +1；引用它的已生效分群回到规则
  校验中，旧最终规模进入「历史规模列表」，在途刷新批次全部作废。
- 并发与一致性：刷新按批次管理，重复发起被幂等拒绝，同批次只有首份完整结果生效；刷新
  失败时分群最终规模与标签覆盖对象数都保持原值。
- 审计追溯：所有动作（含被拒绝的）写入 `audit` 表，`GET /api/segment/{id}/audit` 查分群
  审计，`GET /api/tagmgr/{id}/trace` 从标签定义追到版本快照、分群规模与审计。

## 测试

```bash
cd backend
.venv/bin/python -m unittest discover -s tests -v   # 13 个验收/接口用例
.venv/bin/python -I scripts/e2e_http_check.py       # 需先启动服务，纯 HTTP 全链路冒烟
```

验收覆盖：最小值等于最大值、标签换版、撤销生效、失败重试四类场景，以及异常样例
SEGM-0002（上下限写反 500/50 + 标签 TAGM-NIGHT 草稿）的拒绝与修复全过程。
